# Тестирование GeoMap AI

## Автоматические тесты

```powershell
ctest --test-dir build -C Release --output-on-failure      # Windows, после сборки
ctest --preset windows-release                              # или через пресет
```

```bash
ctest --preset linux-release                                # Linux (QT_QPA_PLATFORM=offscreen)
```

Тесты работают только во временных папках и хранят настройки в отдельном INI, не затрагивая профиль пользователя.

## Ручной чек-лист (UI smoke)

Запускать из переносимой папки; для изоляции настроек — `GeoMapAI.exe --settings-dir <временная папка>`.

1. Запуск: окно открывается, тёмная тема, строка состояния видна (на 1920×1080 при 125 % окно развёрнуто).
2. «+ Создать проект» → «Обзор» → папка с кириллицей и пробелами → «Создать». Кнопка «Создать» неактивна, пока папка не выбрана, в т. ч. после отмены «Обзора».
3. «+ Папка» → набор из 130 снимков: прогресс «Импорт N из M», полоса, имя текущего файла; снимки появляются в списке во время импорта; окно перемещается и реагирует.
4. Итоговый статус с числом пропущенных и причинами; «Пропущенные файлы: N» открывает список.
5. Выбор снимков в списке и ленте; инспектор: размер, объём, камера, дата, GPS; снимок без GPS — «Не обнаружены».
6. «GPS-обзор»: точки на своих местах, выбранная подсвечена.
7. Повторный импорт той же папки — все файлы «уже в проекте».
8. Новый проект, импорт и «Отменить импорт» в середине: статус «Импорт отменён. Импортировано: X из M», в `photos/` ровно X файлов.
9. Закрыть окно во время импорта → подтверждение → «Да»: программа закрывается, скопированные снимки записаны в манифест.
10. Перезапуск, открытие проекта из «Недавних»: все снимки и миниатюры на месте.
11. Горячие клавиши: `Ctrl+S`, `Ctrl+I`, `Ctrl+O`, `Ctrl+W`, `Ctrl+N`.
12. «Открыть папку проекта» открывает Проводник.
13. Второй экземпляр программы, тот же проект → «Проект уже открыт в другом окне».
14. Удаление снимка: подтверждение, копия и миниатюра удалены, оригинал на месте.
15. Ещё не автоматизировано и не выполнено: отказ доступа к папке проекта, нехватка места на диске (проверка места реализована, но не воспроизводилась), пути длиннее 260 символов.

### Обработка (этап B)

16. Вкладка «◈ Обработка»: при первом открытии проверяется окружение; карточка показывает версию Docker, ODM, CPU и память Docker либо причину недоступности и подсказку.
17. Без Docker (`GEOMAP_DOCKER=C:\нет\docker.exe`) — «Docker не найден», запуск недоступен; с неработающей службой (`GEOMAP_DOCKER` указывает на программу, которая завершается с ошибкой) — «Docker не запущен». Остальные функции работают.
18. Без образа — кнопка «Загрузить образ ODM» → диалог с объёмом и лицензией → «Да» → строка состояния загрузки → проверка повторяется.
19. Выбор профиля обновляет проверку: число снимков, GPS, нужное и свободное место, ошибки (красным) и предупреждения.
20. «Запустить обработку» → задание в списке, «Этап k из 13» и журнал обновляются, в нижней строке «Обработка: этап …»; окно отзывчиво.
21. По завершении — результаты с размером, EPSG, размером пикселя, числом точек; «Открыть», «Открыть папку»; список не созданных в режиме результатов.
22. «Отменить» во время работы → «Отменено»; `docker ps -a` не показывает `geomap-odm-*`.
23. Закрыть окно во время обработки → подтверждение → «Да» → задание «Прервано», контейнера нет; после перезапуска история на месте.
24. «Удалить» у завершённого задания → подтверждение → папка `jobs/<id>` удалена, снимки проекта на месте.

## Измерение отзывчивости

Пинг окна через UI Automation искажает результат: подключённый клиент UIA включает в Qt доступность, и отклики окна зависят от самих опросов. Для чистого замера используйте экземпляр, к которому UIA не подключается, и `SendMessageTimeout(WM_NULL)` из отдельного процесса. Причину пауз удобно искать по журналу `QT_LOGGING_RULES=qt.scenegraph.time.renderloop=true` (поля `polish`, `blockedForSync`, интервалы между кадрами GUI-потока).

### Прогон на 1040 снимках

Набор: 1043 файла, 1,68 ГБ (1040 JPEG 4000×3000 с GPS сеткой 26×40, PNG, TIFF, битый JPEG), `generate-test-flight.ps1 -Rows 26 -Cols 40`. Отзывчивость измерялась в экземпляре **без подключения UI Automation** (только Win32-сообщения, клавиатура и клики), `WM_NULL` каждые ~20 мс; время кадров — журналом `qt.scenegraph.time.renderloop`.

| Проверка | До исправления | После исправления |
| --- | --- | --- |
| Импорт 1043 файлов | ~38 с, 1042 импортировано, 1 пропущен | 34,7 с, 1042 импортировано, 1 пропущен |
| Ответы окна во время импорта | 133 замера; медиана 11 мс; 99-й перцентиль 4,9 с; максимум 6,0 с; > 250 мс — 20 | 974 замера; медиана 0 мс; 99-й перцентиль 116 мс; максимум 170 мс; > 250 мс — 0 |
| Фаза `polish` GUI-потока | максимум 6081 мс, кадров > 50 мс — 55 | максимум 78 мс, кадров > 50 мс — 7 |
| GPS-обзор с 1040 точками | — | `polish` ≤ 24 мс |

Причина зависаний: холст GPS-обзора перерисовывался в GUI-потоке при каждой порции импорта, даже скрытый, а в цикле обращался к `projects.geoPoints[i]`. В Qt 6 список, прочитанный из свойства, остаётся привязанным к нему: отдельный эксперимент на Qt 6.8.3 показал 201 вызов геттера при обходе 100 элементов (через метод — 1 вызов). Итог — O(n²) на каждую перерисовку. Исправление: точки берутся одним вызовом `geoPointsSnapshot()`, скрытый холст не перерисовывается.

Прогон с UI Automation (те же 1040 снимков, до исправления): все файлы, миниатюры и записи манифеста — 1042; память процесса 214 МБ; прокрутка списка примерно до 560-го снимка с подгрузкой миниатюр — максимальная задержка ответа 3 мс; закрытие и повторное открытие проекта — без ошибок, stderr пуст. Отдельный прогон на 500 снимках не выполнялся: этот объём пройден внутри прогона на 1040.

## Протокол приёмки встроенного ODM, 0.2.1 (2026-10-14)

Окружение то же. ODM 3.6.2 для Windows, без Docker (служба Docker во время проверки не работала). Папка данных — `--data-dir C:\Users\Lenovo\gmd`.

Важно для воспроизведения: среда, из которой запускались проверки (настольное приложение Claude), упакована в MSIX. Windows перенаправляет записи её дочерних процессов в `%LOCALAPPDATA%` в виртуальную копию, и переименование через NTFS-соединения внутри неё не работает. Поэтому папка данных вынесена за пределы `AppData`. У программы, запущенной обычным образом, такого перенаправления нет.
