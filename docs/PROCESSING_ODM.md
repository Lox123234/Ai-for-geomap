# Фотограмметрическая обработка: OpenDroneMap

GeoMap AI строит ортофотопланы, облака точек, модели рельефа и 3D-модели с помощью [OpenDroneMap](https://github.com/OpenDroneMap/ODM) (ODM) 3.6.2. ODM — отдельная программа с собственной лицензией (AGPL-3.0). GeoMap AI запускает её отдельным процессом, следит за ходом работы и проверяет результаты.

Проекты, импорт, просмотр снимков и GPS-обзор работают и без ODM. Если ODM не установлен, вкладка «Обработка» показывает причину и кнопку установки, а запуск обработки недоступен.

## Режимы работы

| Режим | Что нужно | Когда использовать |
| --- | --- | --- |
| **Встроенный** (Windows, основной) | официальная сборка ODM для Windows: внутри полной поставки GeoMap AI или установленная из программы | всегда на Windows; Docker и WSL не нужны |
| Docker (необязательный) | Docker Desktop или Docker Engine и образ `opendronemap/odm`, закреплённый по digest | Linux; на Windows — если Docker уже настроен (в наших замерах он быстрее, см. ниже) |

«Режим: авто» (по умолчанию) выбирает встроенный ODM, если он найден, иначе Docker. Режим можно выбрать в карточке движка; выбор хранится в настройках. Переменная `GEOMAP_ODM_BACKEND=native|docker` задаёт его при запуске.

Задание продолжается только в том режиме, в котором начато: промежуточные файлы ODM содержат пути этого режима.

## Встроенный ODM

### Где GeoMap AI его ищет

1. `GEOMAP_ODM_HOME` — явный путь к папке ODM;
2. `<папка программы>\engines\odm` — полная поставка GeoMap AI со встроенным ODM;
3. `<папка данных>\engines\odm-3.6.2` — установленный из программы (папка данных: `%LOCALAPPDATA%\GeoMapAI`, параметр `--data-dir` или `GEOMAP_DATA_DIR`);
4. установка, сделанная официальным установщиком ODM (по записи в реестре), и `C:\ODM`.

Подходит папка с `run.py`, `VERSION` 3.6.x, `venv\Scripts\python.exe` и `SuperBuild\install\bin`. Перед запуском GeoMap AI делает то же, что `winpostinstall.bat` ODM: если папку перенесли, перенастраивает `venv\pyvenv.cfg` и загрузчик OpenCV на новое место. Проверка окружения запускает Python ODM с импортом OpenCV и GDAL (меньше секунды) и спрашивает видеокарту у драйвера NVIDIA (`nvidia-smi`).

### Установка из программы

Кнопка «Установить OpenDroneMap» после подтверждения:

1. загружает официальный установщик `ODM_Setup_3.6.2.exe` с GitHub (233,5 МБ) и принимает его, только если SHA-256 совпадает с закреплённым значением `c9dbfabf0d066529a7b6c753fd45bf3366a0314266160cd677373bab4caff294` (неполный или подменённый файл удаляется). Установщик подписан OpenDroneMap;
2. запускает его без окон и **без прав администратора**: `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /CURRENTUSER /NOICONS /DIR=<папка данных>\engines\odm-3.6.2`. Журнал установщика — `<папка данных>\logs\odm-install.log`;
3. кладёт рядом с инструментами ODM недостающие библиотеки VC++ из поставки GeoMap AI (сам установщик ODM ставит их в систему только с правами администратора);
4. выполняет самопроверку ODM (`run.py --version`) и удаляет загруженный установщик.

Установщик ODM добавляет запись «ODM» в «Параметры → Приложения», через неё ODM удаляется. Около 1 ГБ на диске.

**Чужая установка не трогается.** Установщик ODM при установке удаляет другую версию с тем же идентификатором приложения. Поэтому, если в реестре уже есть ODM другой версии или в другой папке, GeoMap AI его не запускает и просит обновить или удалить ту установку самостоятельно.

### Полная поставка «скачал и пользуйся»

`scripts\build-windows.ps1 -OdmDir <папка установленного ODM> -Zip` копирует ODM без изменений в `dist\GeoMapAI\engines\odm` и создаёт архив `GeoMapAI-<версия>-win64-odm.zip`. Деинсталлятор не копируется. Добавляются библиотеки VC++ и файл `SOURCE.txt` со ссылкой на исходный код ODM этой версии. После распаковки такой поставки обработка работает сразу: без Docker, WSL, установщиков и прав администратора. При первом запуске GeoMap AI настраивает `pyvenv.cfg` на новую папку, поэтому распаковывать нужно в папку, доступную для записи (не в `Program Files`).

### Пути с пробелами и кириллицей

Часть компонентов ODM (OpenSfM, OpenMVS, PDAL) открывает файлы через узкие (ANSI) вызовы C и ломается на пробелах и нелатинских символах. При этом ODM пишет вводящее в заблуждение «недостаточно перекрытия»; мы воспроизвели это на папке «Проект с пробелом». Поэтому, если путь задания содержит такие символы, GeoMap AI создаёт NTFS-соединение (junction, без прав администратора) `<ASCII-папка>\work\<id>` на папку задания и передаёт ODM этот путь. После задания соединение удаляется; удаление затрагивает только ссылку. ASCII-папка — это папка данных, её короткое 8.3-имя или `%SystemDrive%\GeoMapAI`.

### Процессы

ODM порождает десятки дочерних процессов (Python, OpenSfM, OpenMVS, GDAL). Все они помещаются в объект задания Windows (Job Object) с флагом «завершать при закрытии»:

- «Отменить» завершает всё дерево процессов сразу;
- при закрытии программы или проекта (после подтверждения) дерево тоже завершается;
- если GeoMap AI аварийно закроется, Windows сама завершит процессы ODM. Проверено: после принудительного завершения GeoMap AI процессов ODM через 3 с не осталось.

Переменные окружения те же, что в `win32env.bat` ODM (`GDAL_DATA`, `PROJ_LIB`, `PATH` только из папок ODM и системы и т. д.), плюс `PYTHONUNBUFFERED=1` для журнала в реальном времени и кэш байт-кода в папке данных вместо `C:\ProgramData`.

### GPU

Встроенная сборка ODM считает признаки SIFT на видеокарте NVIDIA (CUDA, модуль popsift). Проверено на RTX 5050: «Using GPU for extracting SIFT features». Включается выбором «Детектор признаков → SIFT». На наборе из 18 снимков выигрыша по времени нет (15,8 с против 15,2 с у DSP-SIFT на процессоре). Польза ожидается на больших наборах, но мы её не измеряли, поэтому GPU не включается по умолчанию. В режиме Docker GPU не используется.

### Скорость: встроенный ODM против Docker

Набор Brighton Beach (18 снимков), профиль «Быстрый просмотр», один и тот же компьютер (16 потоков, 15,7 ГБ ОЗУ):

| | Docker (WSL 2) | Встроенный |
| --- | --- | --- |
| Извлечение признаков (OpenSfM) | 4,8 с | 15,2 с |
| Все шаги OpenSfM | 12,8 с | 25,0 с |
| Обработка целиком | 52–66 с | 53–54 с; первый запуск свежей поставки — 121 с |

Отдельные шаги OpenSfM в Windows-сборке медленнее, но вся небольшая обработка заняла столько же. Первый запуск после распаковки дольше примерно на минуту. Вероятная причина — разовая компиляция Python-кода ODM и проверка новых файлов антивирусом; она не проверялась. На больших наборах соотношение не измерялось.

## Как проходит обработка

1. **Проверка окружения** при первом открытии вкладки и по кнопке «Проверить снова».
2. **Предварительная проверка** при каждом изменении профиля и параметров. Проверяются: файлы снимков (на месте, не пустые, формат принимается ODM), снимков не меньше 2, наличие GPS, свободное место, допустимость параметров, ресурсы. Ошибки блокируют запуск, предупреждения — нет. Автоматические поправки показываются как «ℹ» и пишутся в журнал. Пример: у снимков нет GPS — тогда `--auto-boundary` отключается.
3. **Задание** — папка `jobs/<id>/` в проекте. Задания идут в очередь, одновременно выполняется одно.
4. **Подготовка** в фоновом потоке: каждый снимок проверяется чтением заголовка и помещается в `jobs/<id>/images/` жёсткой ссылкой на копию из `photos/` (без лишнего места; если жёсткие ссылки недоступны — копией). ODM входные файлы не изменяет; интеграционный тест сверяет SHA-256 снимков проекта до и после обработки. В Docker снимки монтируются только для чтения.
5. **Запуск** — список аргументов без командной оболочки:
   - встроенный режим: `python.exe -X utf8 <ODM>\run.py --project-path <папка> <id> <параметры>`;
   - Docker: `docker run --rm --name geomap-odm-<id> -v <задание>:/datasets/code -v <задание>\images:/datasets/code/images:ro opendronemap/odm@sha256:… --project-path /datasets code <параметры>`.
6. **Ход работы** — вывод ODM пишется в `jobs/<id>/log.txt`, этап показывается как «Этап k из 13». Процентов нет: этапы ODM несопоставимы по длительности.
7. **Завершение** — регистрируются результаты с проверкой файлов и читается отчёт о качестве. Код 0 без результатов считается ошибкой (кроме частичных заданий). Нехватка памяти (код 137, `MemoryError`, `bad_alloc`) сообщается отдельно.

`--max-concurrency` выбирается автоматически: `min(потоков, ГБ памяти − 1)`, но не меньше 1.

## Профили

Параметры задаются в `OdmEngine::profiles()`; при изменении обновите эту таблицу.

| Профиль | Параметры ODM | Результаты | Оценка места |
| --- | --- | --- | --- |
| Только выравнивание | `--feature-quality high --end-with opensfm` | положения камер, разреженное облако, отчёт о качестве выравнивания | 1 × объём снимков |
| Быстрый просмотр | `--fast-orthophoto --feature-quality medium --orthophoto-resolution 10` | ортофотоплан по разреженной реконструкции, 2.5D-сетка, отчёт | 3 × |
| Сбалансированный | `--feature-quality high --pc-quality medium --dsm --orthophoto-resolution 5 --dem-resolution 10 --auto-boundary` | плотное облако, DSM, ортофотоплан, 3D-модель, отчёт | 8 × |
| Высокое качество | `--feature-quality ultra --pc-quality high --dsm --dtm --orthophoto-resolution 2 --dem-resolution 5 --mesh-octree-depth 12 --auto-boundary` | то же + DTM, более детальная сетка | 15 × |

### Пошаговая обработка

Порядок как в настольных фотограмметрических пакетах: сначала выравнивание, затем проверка, затем продолжение.

1. Профиль «Только выравнивание». Задание завершается, когда ODM выровнял снимки.
2. Вкладка «Качество»: выровнено снимков, ошибка репроекции, расхождение с GPS и т. д.
3. Выберите слева другой профиль (и параметры) и нажмите «Продолжить: «<профиль>»». Задание продолжается в той же папке, ODM повторно использует уже готовое выравнивание.

Параметры выравнивания при продолжении не пересчитываются: ODM не отслеживает их изменение. Чтобы выровнять заново с другими параметрами, создайте новое задание.

### Возобновление

Отменённое, прерванное (закрытие программы, сбой) или завершившееся ошибкой задание можно «Продолжить» в его папке. ODM пропускает этапы, результаты которых уже есть. Номер запуска хранится в `job.json` (`runs`), журнал дописывается с пометкой «продолжение». С параметром «Экономить место на диске» (`--optimize-disk-space`) ODM удаляет промежуточные файлы, и возобновление с середины становится невозможным.

## Параметры обработки

Раздел «Параметры обработки» группирует основные настройки ODM по этапам. Пустое значение оставляет значение профиля, заданное — переопределяет его: в разборщике аргументов ODM побеждает последнее значение. Порядок: профиль → параметры → поле для опытных.

| Группа | Параметры (ODM) |
| --- | --- |
| Выравнивание снимков | точность выравнивания (`--feature-quality`), детектор признаков (`--feature-type`: DSP-SIFT, SIFT на GPU, HAHOG, AKAZE, ORB), признаков на снимок (`--min-num-features`), соседей по GPS (`--matcher-neighbors`), алгоритм (`--sfm-algorithm`: инкрементальный, по GPS и углам камеры, плоская сцена), точность GPS (`--gps-accuracy`), rolling shutter (`--rolling-shutter`), гибридная оптимизация (`--use-hybrid-bundle-adjustment`) |
| Плотное облако | качество карт глубины (`--pc-quality`), фильтр выбросов (`--pc-filter`, σ), прореживание (`--pc-sample`), классификация (`--pc-classify`), LAS (`--pc-las`) |
| Модель и рельеф | вершин в модели (`--mesh-size`), глубина октодерева (`--mesh-octree-depth`), без 3D-модели (`--skip-3dmodel`), glTF (`--gltf`), DSM, DTM, разрешение ЦМП/ЦМР (`--dem-resolution`) |
| Ортофотоплан | разрешение (`--orthophoto-resolution`), линия реза (`--orthophoto-cutline`), COG (`--cog`), обзорные уровни (`--build-overviews`) |
| Область и маски | граница по точкам съёмки (`--auto-boundary`), обрезка краёв (`--crop`), удаление неба (`--sky-removal`, экспериментально) |
| Ресурсы | потоков (`--max-concurrency`), разбиение на подмодели (`--split`), экономия места (`--optimize-disk-space`), без GPU (`--no-gpu`) |

Значения проверяются по допустимым значениям и диапазонам из справки ODM 3.6.2. Неизвестный параметр или значение вне диапазона блокирует запуск с понятной ошибкой.

Поле «Параметры ODM для опытных» принимает те же параметры, а также `--fast-orthophoto`, `--skip-report`, `--use-3dmesh`, `--pc-ept`, `--pc-skip-geometric`, `--sfm-no-partial`, `--texturing-single-material`, `--ignore-gsd`, `--split-overlap`, `--dem-gapfill-steps`, `--matcher-type`, `--camera-lens`, `--orthophoto-compression` и `--end-with`. Строка делится на аргументы как командная строка, но никогда не передаётся оболочке. Параметры путей и контейнера (`--project-path` и т. п.) недоступны.

## Отчёт о качестве

Вкладка «Качество» показывает статистику, которую посчитал сам ODM (`odm_report/stats.json`, для выравнивания — `opensfm/stats/stats.json`). GeoMap AI ничего не оценивает сам:

- выровнено снимков (N из M) и предупреждение, если не все;
- число несвязанных частей реконструкции (если больше одной);
- связующих точек, средняя длина трека, ошибка репроекции (RMS, пикс);
- средний GSD, площадь съёмки;
- расхождение с GPS: RMSE X/Y/Z, CE90/LE90; при опорных точках — ошибки по ним;
- число точек облака (плотного или разреженного), фокус камеры до и после уточнения;
- время шагов выравнивания.

Полный PDF-отчёт ODM открывается кнопкой «Открыть» на вкладке «Результаты».

## Результаты

| Вид | Файл в папке задания | Что проверяется |
| --- | --- | --- |
| Ортофотоплан | `odm_orthophoto/odm_orthophoto.tif` | (Big)TIFF и GeoKeys: EPSG, размер пикселя, размер, каналы |
| DSM / DTM | `odm_dem/dsm.tif`, `odm_dem/dtm.tif` | то же |
| Облако точек | `odm_georeferencing/odm_georeferenced_model.laz` (и `.las` с `--pc-las`) | сигнатура `LASF`, версия, число точек |
| 3D-модель | `odm_texturing/odm_textured_model_geo.obj` (и `.glb` с `--gltf`) | наличие, размер, сигнатура glTF |
| 2.5D-модель | `odm_texturing_25d/odm_textured_model_geo.obj` | наличие, размер |
| Отчёт | `odm_report/report.pdf` | сигнатура `%PDF` |

Пустые файлы не регистрируются. «Открыть» запускает программу, связанную с типом файла (для GeoTIFF и LAZ — например, QGIS). Встроенный просмотр карт и 3D — этапы C и D.

## Состояния задания

`queued` → `preparing` → `running` → `completed` / `failed` / `cancelled`; при отмене — промежуточное `cancelling`; `interrupted` — программа или проект закрылись во время работы. Прерванные задания после открытия проекта никогда не показываются завершёнными; оставшийся контейнер Docker или рабочая ссылка удаляются. Удаление задания (с подтверждением) удаляет папку `jobs/<id>/` целиком; снимки проекта не затрагиваются.

## Диагностика

| Сообщение | Что сделать |
| --- | --- |
| «OpenDroneMap не установлен» | «Установить OpenDroneMap» или распакуйте полную поставку со встроенным ODM |
| «Найдена отдельная установка ODM …» | Обновите её до 3.6.2 или удалите (Параметры → Приложения → ODM) и нажмите «Проверить снова» |
| «OpenDroneMap … не запускается» | Переустановите ODM; если программа лежит в папке только для чтения — перенесите её |
| «Контрольная сумма не совпадает» | Файл повреждён или подменён при загрузке; повторите установку |
| нехватка памяти | Профиль попроще, меньше потоков или разбиение на подмодели |
| «Docker не запущен» / «Docker не найден» | Для режима Docker запустите Docker Desktop; либо используйте встроенный ODM |
| «Задание начато в режиме …» | Продолжайте задание в том же режиме или создайте новое |

Время и качество реконструкции не гарантируются: они зависят от перекрытия, качества снимков, GPS/GCP и ресурсов компьютера.

## Сравнение с Agisoft Metashape — честно

GeoMap AI не заменяет движок ODM своим и не делает его «уровня Metashape». Что сделано, чтобы работа была ближе к привычной в настольных пакетах:

- пошаговая обработка (выравнивание → проверка → продолжение);
- отчёт о качестве с ошибкой репроекции и расхождением с GPS (RMSE, CE90/LE90);
- настройки по этапам с понятными названиями и проверкой значений;
- GPU для признаков, автоматическая адаптация параметров к набору, возобновление прерванных заданий.

Чего нет: ручной расстановки маркеров GCP на снимках, ручного редактирования облака, пакетной обработки чанков, сравнения качества с Metashape на одних и тех же данных. Это задачи следующих этапов (GCP и контроль точности — этап F).
