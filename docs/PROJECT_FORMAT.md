# Формат проекта GeoMap AI

Проект — обычная папка. Её можно копировать, архивировать и переносить на другой компьютер: все пути внутри проекта относительные.

```text
Моя съёмка/
  geomap.json          манифест (schemaVersion 1)
  map.json             карта: CRS, вид, слои и их стили (с версии 0.3, schemaVersion 1)
  geomap.lock          блокировка, пока проект открыт (не копировать при резервном копировании)
  vectors/
    drawings.geojson   нарисованные точки, линии, полигоны и измерения (с 0.3)
  photos/
    <uuid>.jpg         копии импортированных снимков (оригиналы не изменяются)
    <uuid>.tif
  cache/
    thumbs/
      <uuid>_jpg.jpg   миниатюры; производные данные, можно удалить в любой момент
    maps/
      <hash>.vrt       пирамиды больших растров (+ .vrt.ovr); производные данные, можно удалить
  jobs/                задания обработки (с версии 0.2), по папке на задание
    20261014-073552/
      job.json         описание и состояние задания (schemaVersion 1)
      log.txt          журнал: заголовок GeoMap AI, команда движка, вывод движка, итог
      images/          входные снимки: жёсткие ссылки на photos/ (или копии)
      odm_orthophoto/  … результаты и рабочие папки OpenDroneMap
```

## `geomap.json`, схема 1

Кодировка UTF-8. Запись атомарная (`QSaveFile`: временный файл → замена).

```json
{
  "schemaVersion": 1,
  "name": "Моя съёмка",
  "createdAt": "2026-10-14T08:00:00.000Z",
  "updatedAt": "2026-10-14T08:05:12.345Z",
  "photos": [
    {
      "id": "51dc…e3",
      "file": "photos/51dc…e3.jpg",
      "name": "DJI_0001.JPG",
      "sourcePath": "D:/DCIM/100MEDIA/DJI_0001.JPG",
      "cameraMake": "DJI",
      "cameraModel": "FC3411",
      "takenAt": "2026:09:20 10:00:02",
      "bytes": 1650000,
      "width": 4000,
      "height": 3000,
      "hasGps": true,
      "latitude": 43.23,
      "longitude": 76.93
    }
  ]
}
```

| Поле | Смысл |
| --- | --- |
| `id` | UUID снимка в проекте |
| `file` | Путь к копии; **только** вида `photos/<имя>` |
| `name` | Исходное имя файла (для показа) |
| `sourcePath` | Канонический путь оригинала. Только для информации и поиска дубликатов; для открытия проекта не нужен |
| `cameraMake`, `cameraModel`, `takenAt` | Из EXIF; пустая строка, если данных нет (ничего не додумывается) |
| `bytes`, `width`, `height` | Размер файла и изображения |
| `hasGps`, `latitude`, `longitude` | Координаты WGS 84 из EXIF; поля координат есть только при `hasGps: true` |

## Правила чтения

- Файл больше 64 МиБ, некорректный JSON, корень не объект, `schemaVersion ≠ 1` или `photos` не массив — проект не открывается, ранее открытый проект остаётся открытым.
- Записи, у которых `file` выходит за `photos/` (`..`, подпапки, `\`, буквы дисков, абсолютные пути), пропускаются.
- Записи, чей файл отсутствует, пропускаются; при следующем сохранении они исчезнут из манифеста.
- Координаты вне диапазона (|широта| > 90, |долгота| > 180) или нечисловые — `hasGps` сбрасывается.

## Импорт

- Снимки **копируются** в `photos/` под новым UUID; оригинал не изменяется. Копия делается записываемой, даже если оригинал «только для чтения».
- Импорт идёт в фоновом потоке. Манифест сохраняется каждые 2 с во время импорта и в конце; при отмене или закрытии окна всё уже скопированное записывается в манифест.
- Перед импортом проверяется свободное место: размер новых файлов + 64 МиБ запаса.

## Миниатюры

`cache/thumbs/` содержит JPEG не больше 320 px по длинной стороне, с учётом EXIF-ориентации. Миниатюра пересоздаётся, если её нет, она повреждена или старше снимка. Удаление снимка из проекта удаляет и его миниатюру.

## Задания обработки: `jobs/<id>/job.json`, схема 1

Задания не входят в `geomap.json`: каждое описано своим файлом и может быть удалено вместе с папкой, не трогая манифест. `id` — время создания `yyyyMMdd-HHmmss` (при совпадении добавляется `-2`, `-3`, …); он же имя папки задания. Запись атомарная (`QSaveFile`).

```json
{
  "schemaVersion": 1,
  "id": "20261014-073552",
  "engine": "odm",
  "engineVersion": "3.6.2",
  "backend": "native",
  "runs": 1,
  "notes": [],
  "profile": "fast",
  "arguments": ["--fast-orthophoto", "--feature-quality", "medium", "--orthophoto-resolution", "10", "--max-concurrency", "6"],
  "state": "completed",
  "message": "Готово. Результатов: 4.",
  "stage": "odm_postprocess",
  "stageIndex": 13,
  "stageCount": 13,
  "createdAt": "2026-10-14T02:35:52.104Z",
  "startedAt": "2026-10-14T02:35:52.290Z",
  "finishedAt": "2026-10-14T02:37:03.611Z",
  "images": ["photos/51dc…e3.jpg", "…"],
  "exitCode": 0,
  "outputs": [
    {"kind": "orthophoto", "file": "odm_orthophoto/odm_orthophoto.tif", "bytes": 6215873,
     "details": "EPSG:32615, 10,0 см/пикс, 1056×848, каналов: 4"}
  ]
}
```

| Поле | Смысл |
| --- | --- |
| `state` | `queued`, `preparing`, `running`, `cancelling`, `completed`, `failed`, `cancelled`, `interrupted` |
| `backend` | среда выполнения: `native` (встроенный ODM). `docker` — у заданий 0.2.x, выполненных в Docker (0.2.0 без поля тоже считаются `docker`): их результаты читаются, продолжить их нельзя |
| `runs` | сколько раз задание запускалось (возобновление продолжает в той же папке) |
| `notes` | автоматические поправки параметров, например отключённый `--auto-boundary` у снимков без GPS |
| `stage`, `stageIndex`, `stageCount` | последний этап, о котором сообщил движок, и его место в списке этапов движка; `0` — этапов ещё не было |
| `images` | снимки проекта, вошедшие в задание (пути вида `photos/<имя>`) |
| `arguments` | итоговые параметры движка (профиль + дополнительные + `--max-concurrency`) |
| `outputs` | результаты, найденные и проверенные после завершения; `file` — относительно папки задания |
| `exitCode` | код завершения процесса движка |

При открытии проекта задание в активном состоянии (`queued` … `cancelling`) переводится в `interrupted`: значит, программа остановилась во время обработки. Файлы `job.json`, которые не читаются, пропускаются (папка остаётся на диске). Подробности обработки — `docs/PROCESSING_ODM.md`.

## Карта: `map.json`, схема 1 (с 0.3)

Пишется атомарно (`QSaveFile`) через полсекунды после изменения и при закрытии проекта. Файл не нужен для открытия проекта: без него карта строится заново.

```json
{
  "schemaVersion": 1,
  "crs": "PROJCRS[\"WGS 84 / UTM zone 15N\", …]",
  "crsEpsg": 32615,
  "crsNote": "UTM-зона 15N по положению данных (точки съёмки)",
  "view": {"x": 576700.5, "y": 5188150.2, "resolution": 0.12},
  "layers": [
    {"id": "93cce51f5dcd", "type": "raster", "name": "odm_orthophoto",
     "source": "jobs/20261014-150853/odm_orthophoto/odm_orthophoto.tif",
     "visible": true, "opacity": 1, "color": "#ffc43d",
     "style": {"mode": "rgb", "red": 1, "green": 2, "blue": 3, "alpha": 4, "rgbMin": [0, 0, 0], "rgbMax": [255, 255, 255],
               "band": 1, "ramp": "terrain", "min": 154.5, "max": 172.0, "hillshade": false}},
    {"id": "0c5d5e000001", "type": "raster", "name": "dsm-без-crs", "source": "D:/Данные/dsm.tif",
     "crs": "PROJCRS[…]", "visible": true, "opacity": 0.8, "color": "#ffc43d"},
    {"id": "a1b2c3d4e5f6", "type": "vector", "name": "Границы", "source": "D:/Данные/участки.gpkg", "layer": "parcels",
     "visible": true, "opacity": 1, "color": "#7ed321"},
    {"id": "photos", "type": "photos", "name": "Точки съёмки", "visible": true, "opacity": 1, "color": "#ff9f43"},
    {"id": "drawings", "type": "drawings", "name": "Рисунки и измерения", "visible": true, "opacity": 1, "color": "#54d6ff"}
  ]
}
```

| Поле | Смысл |
| --- | --- |
| `crs`, `crsEpsg` | CRS карты (WKT2 и код EPSG, если он есть). Пусто — CRS ещё не выбрана |
| `crsNote` | откуда взята CRS: «UTM-зона … по положению данных», «по слою …», «пользователем» |
| `view` | центр в координатах CRS карты и разрешение (единиц CRS на пиксель экрана) |
| `layers` | снизу вверх (последний рисуется поверх). `photos` и `drawings` есть всегда |
| `source` | файл слоя: путь относительно папки проекта, если файл внутри неё (результаты обработки), иначе абсолютный |
| `layer` | имя слоя внутри многослойного векторного файла (GeoPackage) |
| `crs` у слоя | CRS, **указанная пользователем** для файла без CRS. У файлов со своей CRS поля нет |
| `style` | стиль растра: `mode` `rgb` (каналы `red`/`green`/`blue`, `alpha`, диапазоны) или `single` (`band`, шкала `ramp` = `gray`/`terrain`/`spectral`, `min`/`max`, `hillshade`) |

Если файл слоя пропал или не читается, слой остаётся в списке с сообщением об ошибке; ничего не удаляется.

## Рисунки: `vectors/drawings.geojson`

GeoJSON (RFC 7946, WGS 84, 7 знаков после запятой — около 1 см). Свойства: `name`; у линий `length_m`, у полигонов `area_m2` и `perimeter_m` — геодезические значения на момент сохранения (при открытии пересчитываются). Файл можно открыть в любой ГИС.

## Блокировка

`geomap.lock` создаётся `QLockFile`, пока проект открыт. Второй процесс GeoMap AI не может открыть тот же проект и показывает сообщение. Блокировка процесса, который аварийно завершился, распознаётся и заменяется. Если в папку нельзя писать (носитель только для чтения), проект открывается без блокировки, а статус сообщает об этом.

## Совместимость

- Проекты 0.1.0 открываются в 0.1.1 без изменений; `cache/` и `geomap.lock` появляются автоматически.
- Проекты 0.1.x открываются в 0.2 без изменений; `jobs/` появляется при первой обработке. Версии 0.1.x папку `jobs/` игнорируют.
- 0.2.1 добавляет в `job.json` необязательные поля `backend`, `runs`, `notes` (схема остаётся 1). Задания 0.2.0 читаются как выполненные в Docker.
- 0.3.0 добавляет `map.json`, `vectors/` и `cache/maps/`. Проекты 0.2.x открываются без изменений; версии 0.2.x эти файлы игнорируют.

## Данные программы вне проектов

Папка данных (`%LOCALAPPDATA%\GeoMapAI`, или `--data-dir`, или `GEOMAP_DATA_DIR`) содержит то, что не относится к проектам: `engines\odm-3.6.2` (установленный из программы ODM), `downloads` (временные загрузки), `work` (временные ASCII-ссылки на папки заданий, существуют только во время работы), `cache\odm-pycache`, `logs`. Ни один проект не зависит от этой папки.
- Любое изменение схемы увеличивает `schemaVersion` и сопровождается миграцией с резервной копией манифеста. Механизм миграций будет добавлен вместе с первым изменением схемы.
